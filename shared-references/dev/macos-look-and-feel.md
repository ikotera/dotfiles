# macOS の見た目と操作感

似た機能の標準アプリ（参照アプリ）がある場合は、それに全面的に合わせて洗練度を上げる。判断の基準は、**その時点の最新の macOS で動く参照アプリの実物**と、Apple の HIG（Human Interface Guidelines、ヒューマンインターフェイスガイドライン）。記憶や古いスクリーンショットではなく、実機で並べて比べる。

## 進め方

1. PLAN 冒頭の「参照アプリ」と §3 に、参照アプリと版（macOS の版）を書く。
2. §3 の対応表に、下のチェック項目ごとに「参照アプリではどうなっているか」「このアプリでどうするか」「状態」を書く。合わせない項目は理由を書く。
3. 画面を作るステップごとに、参照アプリとこのアプリを同じ大きさのウィンドウで撮って並べ、違いを列挙して直す（`screencapture -l <ウィンドウID>`。`[[macOS GUIアプリの自動操作テスト]]`）。
4. ライトモードとダークモードの両方で確かめる。

## チェック項目

### ウィンドウと配置
- [ ] タイトルバーとツールバーの一体化、信号機ボタン（閉じる・最小化・拡大）の位置と余白
- [ ] サイドバーの幅・半透明の素材・セクション見出し（「よく使う項目」「場所」「タグ」等）の書体と色
- [ ] サイドバーとコンテンツの境界、ペインの幅の変更と記憶
- [ ] パスバー・ステータスバーの有無と内容（版の表示もここに置くと見た目を崩しにくい）
- [ ] ウィンドウの大きさ・位置・表示状態の記憶（次回起動時に戻す）

### 部品と書体
- [ ] 書体はシステムフォント（SF Pro・ヒラギノ）、大きさは参照アプリと同じ（本文 13pt 前後）
- [ ] アイコンは SF Symbols、ファイルは OS のアイコン（既定アプリのアイコン）を使う
- [ ] 角丸・行の高さ・選択の色（アクセントカラーに従う）・フォーカスリング
- [ ] ボタン・検索欄・トグルの形と大きさ
- [ ] ダークモードと、OS のアクセントカラー・強調表示の色への追従

### 操作
- [ ] 標準のキー割り当て（⌘, 設定 / ⌘W 閉じる / ⌘Q 終了 / ⌘Z・⇧⌘Z 取り消し・やり直し / ⌘F 検索 / ⌘A 全選択 / ⌘C・⌘V / Space Quick Look / ⌘⌫ ゴミ箱 / ⌘[ ⌘] 戻る・進む / ⌘↑ 上の階層 / ⌘↓・Return の役割は参照アプリに合わせる）
- [ ] ツールバーのボタンにマウスを載せると、ショートカットを含むヘルプが出る
- [ ] 右クリックメニューの項目・並び・区切り線・サブメニュー（マウスを載せて開く）を参照アプリと同じにする
- [ ] メニューバー（アプリ名 / ファイル / 編集 / 表示 / ウインドウ / ヘルプ）と、各項目のショートカット表示
- [ ] ダブルクリック・ドラッグ＆ドロップ・複数選択（⌘ と ⇧ のクリック）・型番選択（文字を打って項目へ飛ぶ）
- [ ] 取り消し（⌘Z）がファイル操作にも効く
- [ ] 設定画面は ⌘, で開く独立したウィンドウ。変更は即座に反映し、再起動後も保つ

### 動きとアクセシビリティ
- [ ] アニメーションは短く控えめに。「視差効果を減らす」設定に従う
- [ ] 文字の大きさの設定、VoiceOver で主な操作が読み上げられるか（GPUI 等の自前描画では限界がある。PLAN §3 に現状を書く）

## 自前で描くフレームワーク（GPUI 等）で起きやすい問題

knowledge-base の MOC `[[Rust製macOSアプリ開発]]` に実例がある。

- 透明タイトルバーにボタンを並べると、連打がタイトルバーのダブルクリックとみなされて拡大する（`[[透明タイトルバーの誤ズーム]]`）
- 起動直後にフォーカスが無いと、キー割り当てとメニューが効かない（`[[GPUIの初期フォーカス]]`）
- モーダルの背景がイベントを遮り、ドラッグが効かない（`[[GPUIのドラッグ＆ドロップとイベント遮蔽]]`）
- 画像のキャッシュがメモリと GPU に残り続ける（`[[GPUIの画像キャッシュ解放]]`）
- 日本語入力の変換中の選択範囲の計算を誤ると強制終了する（file-classifier の S10 前後で修正）
