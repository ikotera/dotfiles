# Obsidian用規約

## 保存ディレクトリ

- vault のルート: ローカル実行環境（ローカルファイルシステムから `~/Github/knowledge-base` に直接アクセスできるセッション）では `~/Github/knowledge-base`。クラウド／リモート実行環境（Claude Code on the web 等、ローカルに `~/Github/knowledge-base` が存在しないセッション）では、GitHub リポジトリ `ikotera/knowledge-base` を直接の出力先とする。セッションにこのリポジトリをアタッチ／クローンし、そのワーキングツリーに書き出したうえで commit・push する。push 先のブランチは `dotfiles/instructions/shared-instructions.md` の「Git ブランチ運用」に従う（既定は `main` への直接 push）。
- `~/Github/knowledge-base` は GitHub リポジトリ `ikotera/knowledge-base` の origin を指すローカル clone であり、両者は同一リポジトリ。ローカル実行環境で commit・push した変更も、クラウド／リモート実行環境から見えるのと同じ `ikotera/knowledge-base` に反映される。
- 以下は vault ルートからの相対パス。

- distill：`01_Distills`
- MOC：`02_MOC`
- atomic note：`03_Atomic-notes`
- daily note：`04_Daily-notes`
- manual：`05_Manuals`

## 整形規約

- 整形規約: セッション中の数式等は LaTeX の `\(...\)` や `\[...\]` が使われておりこのままでは Obsidian で正しくレンダリングされないため、インライン数式は `$...$` に、独立数式は `$$...$$` に変換する。

## 堅牢性の歯止め

- 語彙は `vocabulary.md` を唯一の真実源とする。
- `kb.base` に「規約違反を炙り出すビュー」を置く（例: `domain` 未設定、`type` が語彙外、`status` 不整合）。揺れが入った瞬間に可視化する。

## 命名規約

- タイトル（H1）＝ファイル名。
- 日本語を優先する。ただし、英語名が定着しているものは英語のままにする。
- 評価語、冗長な助詞、結果語を避ける。
- `: / \ * ? " < > | # ^ [ ] |` など、ファイル名や Wikilink を壊す記号を使わない。
- 長い言い換え・略語・和英表記はタイトルではなく `aliases` に置く。

## Wikilink規約

- ノート自身のファイル名または H1 をリンク先にした自己参照 Wikilink を作らない。たとえば `分散ローカルメモリ.md` の本文では `[[分散ローカルメモリ]]` や `[[分散ローカルメモリ|ローカルメモリ]]` を使わず、通常のテキストとして記載する。
- 自己参照 Wikilink はナビゲーションにならず、バックリンクやグラフに不要な自己ループを作るため、既存のものを見つけた場合もリンク記法を外す。
- `[[#見出し]]`、`[[ノート名#見出し]]`、`[[#^ブロックID]]` のような同一ノート内へのリンクも自己参照 Wikilink として作らない。

## 元ノート編集ルール

- 元ノートの論旨・段落構造・語調を変えない。
- リンク化のためだけに文章を大きく書き換えない。
- 同じ語を機械的に全置換しない。文脈上リンクとして意味がある箇所だけを置換する。
- コード、コマンド、URL、引用元の原文は壊さない。
